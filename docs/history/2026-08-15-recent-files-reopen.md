# 최근 파일 목록에서 바로 열기 (이슈 #125)

## 요청

> 열었던 파일 목록을 볼수 있는 기능을 추가해줘.
> → (확인 후) 목록에서 선택시 파일을 바로 열어줘.

## 먼저 확인한 것 — 기능은 이미 있었다

요청받은 "열었던 파일 목록" 은 **F-36 으로 이미 구현돼 있었다**(툴바 시계 아이콘,
단위 31 + E2E 12건). 그대로 개발을 시작했다면 중복 기능을 만들고 백로그에 남겼을 것이다.

그래서 이슈를 만들기 전에 멈추고 현재 상태와 실제 빈틈 세 가지를 정리해 확인을 받았다:
단축키 없음 · **새로고침 뒤 바로 열리지 않음** · 경로가 보이지 않음.
사용자가 고른 것은 두 번째다.

## 무엇이 막혀 있었나

| 상황 | 수정 전 |
|------|---------|
| 이번 세션에서 연 파일 | ✅ 바로 열림 |
| **새로고침 후** | ❌ 파일 선택 창 |
| Safari · Firefox | ❌ 파일 선택 창 (FS Access API 없음) |

`FileSystemFileHandle` 이 **JSON 으로 직렬화되지 않아** 세션 저장(localStorage)에는
이름과 시각만 들어갔고, 핸들은 `main.ts` 의 `Map` 에서 세션 동안만 살았다.

## 해결

**IndexedDB 는 구조화 복제(structured clone)를 쓰므로 핸들을 그대로 담는다.**
"직렬화가 안 된다" 와 "IndexedDB 에 못 넣는다" 는 다른 이야기이고, 이 구분이 해결책 전부다.

| 파일 | 역할 |
|------|------|
| `src/handleStore.ts` (신규) | IndexedDB 보관 + 권한 판단. 플랫폼 API 주입 경계 |
| `src/recentFilesUi.ts` | 상태가 둘 → 셋. 보관 경로 클릭 처리 |
| `src/main.ts` | 파일을 열/저장할 때 핸들 보관, 세 콜백 주입 |

### 권한은 자동으로 복원되지 않는다

되살린 핸들에 권한은 따라오지 않는다. `queryPermission({ mode: "readwrite" })` 로 확인하고
없으면 요청하는데, **이 호출은 클릭 핸들러 안이어야 한다** — 사용자 제스처 밖에서는 조용히
거부된다. 그래서 **앱 기동 시 자동 복원은 하지 않는다**: 누르지도 않았는데 권한 창이 뜨면
그건 앱이 아니라 침입이다.

`read` 가 아니라 `readwrite` 로 묻는다. 읽기 권한만 받으면 그 다음 저장에서 다시 막힌다.

### 상태가 둘에서 셋으로

| 상태 | 누르면 | 표시 |
|------|--------|------|
| `live` | 바로 열림 (변화 없음) | 상대 시간 |
| **`stored`** | 접근 한 번 허용하면 열림 | 상대 시간 · 접근 허용 필요 |
| `stale` | 파일 선택 창 (예전 동작) | 다시 선택 필요 |

`stored` 를 `live` 처럼 보이게 하지 않았다. 권한 창이 뜰 수 있다는 것을 숨기면
**기대와 다른 창이 뜨는데, 그것이 이 기능의 유일한 실패 모드**다.

## 검증 — 목 핸들로는 아무것도 증명할 수 없었다

기존 `installFsMock()` 의 핸들은 **메서드를 가진 평범한 객체**라 구조화 복제가 아예 안 된다
(`DataCloneError`). 그것으로 "핸들을 보관한다" 를 검증하면 통과해도 아무것도 증명하지 못한다.

OPFS(`navigator.storage.getDirectory()`)는 **파일 선택 창 없이 실물 `FileSystemFileHandle`**
을 주므로, `installRealHandleMock()` 으로 전제를 진짜 객체로 확인한다. `RS0` 이
"브라우저가 진짜 핸들을 IndexedDB 에 담았다가 되살려 **실제 내용을 읽는다**" 를 단언한다.

### E2E 자체의 거짓 통과를 두 번 잡았다

| 함정 | 증상 |
|------|------|
| 저장 직후 디스크를 **한 번만** 읽음 | 스왑 커밋 중간 상태(새 내용 + 옛 꼬리)가 보임 — 5회 중 2회 실패 |
| 세션이 복원한 내용을 "열렸다" 의 증거로 씀 | 조건이 곧바로 참 → 그 뒤 편집이 새 탭에 덮어써 **옛 내용이 저장됨** — 5회 중 2회 |

고친 뒤 30회 반복 실행 전부 통과. 둘 다 `CLAUDE.md` 트랩 76·77 로 남겼다.

### 의도적 버그 주입 7건 — 전부 잡힘

보관 미실행 / 권한 미확인 / 권한이 있어도 매번 재요청 / `read` 권한으로 요청 /
목록 삭제 시 핸들 미삭제 / `stored` 를 `live` 처럼 취급 / 대화상자 열 때 보관 목록 미갱신.

**잡히지 않는 것 하나를 알고 남겼다**: 권한 요청을 클릭 핸들러 밖으로 옮기면 조용히
거부되는데, 이것은 테스트로 잡을 수 없다. 주석과 트랩 #6 으로 규칙화했다.

## 문서 정정

`CLAUDE.md` 트랩 **#6** 이 "파일 핸들은 직렬화할 수 없다" 였다. IndexedDB 경로가 생겼으므로
이 문구는 더 이상 사실이 아니다 — "**JSON 으로** 직렬화할 수 없다" 로 고치고, IndexedDB 는
담긴다는 것과 권한 제약을 함께 적었다.
