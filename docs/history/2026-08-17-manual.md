# 사용 설명서 + 툴바 매뉴얼 버튼 (이슈 #141)

## 요청

> 매뉴얼 문서를 md로 작성해서 메뉴얼 버튼을 만들어서 연결해줘.

## 왜 필요했나

이 앱은 웹이라 **메뉴바가 없다.** 기능이 80여 개인데 알 수 있는 방법이 툴바 아이콘과
단축키 안내뿐이었다. `docs/` 문서는 전부 개발자용이고, 유일한 비개발자용 문서
(`how-it-works.md`)는 "어떻게 동작하나" 지 **"어떻게 쓰나" 가 아니다.**

## 만든 것

| 파일 | 역할 |
|------|------|
| `docs/manual.md` (신규) | 사용법 12절 — 단일 출처 |
| `src/manualView.ts` (신규) | `<dialog>` 주입형 리프 |
| `src/toolbar.ts` | **Manual** 버튼(책 아이콘) — Shortcuts 옆 |
| `vite.config.ts` | 기존 번들 플러그인 확장 (`virtual:manual`) |

문서는 **코드에서 사실을 확인해** 썼다 — 단축키는 `shortcutDefs.ts`, 툴바 라벨은
`toolbar.ts`, 브라우저별 저장 차이는 `fileOps.ts`. `⌘N` 이 아니라 `⌥N` 인 이유
(브라우저가 선점)처럼 **"왜" 까지** 담았다.

## 판단 세 가지

### 1. 새 탭이 아니라 대화상자

탭으로 열면 마크다운 편집기가 자기 문서를 자기 프리뷰로 보여주는 셈이라 자연스러워
보인다. 그런데 그러면 **사용자가 그 탭을 고치고 저장하려 든다** — 실제 파일이 아니라
저장할 곳이 없고, 세션에도 남아 다음에 열 때 "안 지운 문서" 처럼 보인다.

E2E `MA8` 이 "설명서를 열어도 탭 수와 편집 중인 문서가 그대로" 를 단언한다.

### 2. 받아오지 않고 빌드 시각에 번들

`fetch("/manual.md")` 하나면 이 앱의 "공유 외 네트워크 요청 0건" 이 깨지고 E2E `SH8`
이 죽는다(트랩 #75). `CHANGELOG.md`(#131)와 **같은 플러그인을 확장**했다 — 가상
모듈이라 원본을 고치면 그대로 반영되고 낡을 수 없다.

플러그인을 새로 만들지 않은 이유: 거의 같은 코드가 둘이 되면 한쪽만 고쳐지는 날이 온다.

### 3. 본문은 `parseMarkdown()` 을 거친다

정화 경로는 하나뿐이다(F-18). 여기서 직접 HTML 을 조립하면 두 번째 경로가 생긴다.

## 검증 중 잡은 것 두 가지

### `<dialog>` 에 `display` 를 무조건 주면 닫혀도 안 사라진다

헤더(제목·닫기 버튼)를 고정하려고 `display: flex` 를 줬더니 **닫기가 동작하지 않았다.**
`<dialog>` 는 닫혀 있을 때 UA 가 `display: none` 으로 숨기는데 그것을 덮어썼기 때문이다.

기능은 멀쩡하고 화면만 안 닫히므로 **원인을 JS 에서 찾게 된다.** `dialog[open]` 으로
한정했다. 트랩 #84.

### 내가 쓴 E2E 단언 하나가 무력했다

"본문이 스크롤 컨테이너인가" 를 확인하려고 `.manual-body` 의 `overflow-y` 를 지우는
주입을 넣었는데 **통과했다.** `.shortcut-help-list` 가 이미 `overflow-y: auto` 를 주고
있어 제거가 무효였던 것이다.

**닫기 버튼이 화면에 남아 있는지**를 단언하도록 바꿨다. 이쪽이 옳은 단언이기도 하다 —
실제 위험은 "긴 문서를 내려 읽다 닫을 방법이 사라지는 것" 이지 CSS 속성 자체가 아니다.
바꾼 뒤 헤더 고정을 없애는 주입으로 실패를 확인했다.

## 승격에서 낸 오판 — 다른 워크플로 실행을 봤다

머지 직후 `gh run list --branch main --limit 1` 로 실행을 잡았는데, **그 시점에 새
실행이 아직 만들어지지 않아 이전 버전(v2.2.0)의 실행을 붙잡았다.** 그것이 `success`
로 끝나 있어 배포가 완료된 줄 알고 넘어갔고, 결과적으로

- 헬스체크가 `VERSION=0181cfc`(옛 버전)로 **실패**
- `v2.3.0` 릴리스가 **"없음"**

으로 나왔다. 배포가 실패한 것이 아니라 **내가 다른 실행을 본 것**이었다.

`origin/main` 의 SHA 로 실행을 특정해 다시 기다리니 정상 완료됐다.

> **다음부터는 실행을 SHA 로 특정한다:**
> ```bash
> SHA=$(git rev-parse origin/main)
> RUN=$(gh run list --branch main --limit 5 --json databaseId,headSha \
>       -q ".[] | select(.headSha==\"$SHA\") | .databaseId" | head -1)
> ```
> 헬스체크가 SHA 를 대조하는 설계(트랩 #19) 덕분에 이 오판이 곧바로 드러났다 —
> 그것이 없었다면 "배포됐다" 고 보고하고 넘어갔을 것이다.

## 남은 것

- 설명서에 **그림이 없다.** 글로만 설명하므로 "툴바의 책 아이콘" 같은 표현이 실제
  아이콘과 연결되지 않을 수 있다. 스크린샷을 넣으려면 번들 크기와 갱신 부담을
  함께 판단해야 한다
- 한국어만 있다
- 설명서를 여는 **단축키가 없다.** 툴바 버튼뿐이다 — 단축키를 더하려면
  `shortcutDefs.ts` 에만 추가하면 안내에도 자동 반영된다(트랩 #24)
