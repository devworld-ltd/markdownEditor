# 2026-08-14 · 스크롤 블록 앵커 (이슈 #114)

## 1. 요청 사항

> `/aiops:devflow 스크롤 할때, 양쪽의 내용 라인이 틀어지는 문제를 해결해줘.`

F-25 스크롤 동기화는 처음부터 **스크롤 가능 거리의 비율**로 두 패널을 연동했다. 값은 정확히 비례하지만, 사용자가 보는 것은 값이 아니라 **내용**이다.

## 2. 원인

같은 원문이라도 두 패널의 높이 분포가 다르다.

| 요소 | 편집기 | 프리뷰 |
|------|--------|--------|
| `# 제목` | 한 줄 | 큰 글씨 + 위아래 여백 |
| ` ```ts …``` ` | 펜스 포함 줄 수 그대로 | 패딩 + 배경이 붙은 상자 |
| 표 | 원문 줄 수 | 셀 높이에 따라 달라짐 |

비율은 문서 **전체**를 하나의 선형 대응으로 본다. 국소적으로 높이비가 다른 지점이 있으면 그 오차가 문서 중간에서 최대가 된다 — 실측에서 제목 하나가 화면 한 칸 넘게 어긋났다.

## 3. 해결 — 블록 앵커

원문의 최상위 블록이 시작하는 줄과 프리뷰의 최상위 자식을 **순서대로 짝지어**, 스크롤을 그 대응 위에서 보간한다. 오차가 문서 전체가 아니라 **블록 안**에 갇힌다.

```
원문 블록 시작 줄  →  편집기 y (미러 측정)  ┐
                                          ├→ 앵커 → 선형 보간 → 반대편 scrollTop
프리뷰 최상위 자식 →  프리뷰 y (경계 상자)  ┘
```

| 판단 | 근거 |
|------|------|
| 개수가 다르면 **포기**하고 비율로 되돌아간다 | 틀린 대응표는 스크롤을 제멋대로 튀게 한다 — 안 맞추느니만 못하다 |
| 단조 증가가 깨진 앵커는 버린다 | 측정 잡음 하나로 그 구간이 **역주행**한다 |
| 양 끝은 끝점에 맞춘다 | "맨 위·맨 아래는 정확히 같다" 는 F-25 의 기존 계약 |
| 렌더 뒤 **한 번만** 측정하고 캐시 | 스크롤은 프레임마다 도는 경로다 |
| 소유권·메아리 모델(R1~R3)은 그대로 | 앵커는 **목표 좌표만** 바꾼다. 여기를 건드리면 무한 루프가 돌아온다 |

측정은 미러 한 장에 표식 `<span>` 을 심어 **한 번의 레이아웃**으로 전부 읽는다. 지점마다 미러를 만들면 O(n²) 이 되어 타이핑이 멈춘다.

## 4. 검증에서 드러난 것 — 테스트가 틀렸던 두 번

E2E 를 처음 짰을 때 두 건이 실패했는데, **둘 다 앱이 아니라 테스트가 틀렸다.**

| 실패 | 진짜 원인 |
|------|-----------|
| 문서 끝 근처 제목이 프리뷰 상단에 안 옴 | 프리뷰가 더 짧아 **거기까지 스크롤할 수 없다.** 맨 아래가 정답이다 — 단언을 "화면 안에 보인다" 로 바꿨다 |
| 프리뷰 → 편집기 방향이 어긋남 | 테스트가 편집기 상단 줄을 `scrollTop / lineHeight` 로 어림했다. **긴 문단이 접히면 곧바로 틀린다** — 앱과 같은 미러 기법으로 바꿨다 |

실측으로 확인한 정확도: 앵커 지점에서 **오차 0px**(제목 8·20 에서 프리뷰 scrollTop 이 블록 top 과 정확히 일치).

## 5. 의도적 버그 주입

| 주입 | 잡은 테스트 |
|------|-------------|
| 개수 불일치에도 짝짓기 강행 | 단위 |
| 단조 증가 검사 제거 | 단위 |
| 보이지 않는 토큰도 대응표에 포함 | 단위 13건 |
| 앵커를 무시하고 항상 비율 | E2E 4건 |
| 앵커 캐시를 무효화하지 않음 | E2E 4건 |
| 미러 폭을 고정값으로 (좌표 어긋남) | E2E 5건 |

## 6. 남은 과제

| 항목 | 내용 |
|------|------|
| 각주 문서 | 프리뷰에 각주 절이 하나 더 붙어 개수가 어긋난다 → 앵커가 꺼지고 비율로 동작한다. 대응표에 "원문 없는 블록" 개념을 넣으면 풀린다 |
| 블록 내부 | 아주 긴 코드블록 안에서는 여전히 선형 보간이라 중간이 어긋날 수 있다 |
