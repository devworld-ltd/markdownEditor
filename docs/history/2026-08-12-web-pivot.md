# 2026-08-12 · macOS 네이티브 앱 → 웹 기반 마크다운 에디터 전환 (v2.0.0)

## 1. 요청 사항

> "이 프로젝트의 방향을 web 기반 마크다운 에디터로 변경해줘."

방향 전환의 범위가 갈리는 지점 3개를 확인받고 진행했다.

| 결정 사항 | 선택 |
|-----------|------|
| 네이티브 macOS 앱 | **제거하고 웹 전용 전환** |
| 브라우저 파일 I/O | **File System Access API + 폴백** (localStorage 자동 저장 병행) |
| 배포 | **Cloudflare Workers** (dev/prod) |

## 4. 전환 중 발견해 수정한 버그 3건

| # | 심각도 | 버그 | 원인 | 수정 |
|---|--------|------|------|------|
| 1 | 높음 | New/Open/Save 버튼을 누르면 문서가 즉시 dirty 로 표시 | `initToolbar()` 가 **모든** 버튼 클릭 후 `input` 이벤트를 재발행 | `editsText` 플래그로 서식 액션 12개만 재발행 |
| 2 | 중간 | 탭 전환 시 커서가 항상 0,0 으로 초기화 | 포커스 없는 textarea 의 선택 영역을 브라우저가 클릭 이벤트 종료 시 되돌림 | `switchTab()` 에서 `focus()` 후 선택 복원 |
| 3 | 낮음 | jsdom 단위 테스트에서 `localStorage` 접근 불가 | Node 22+ 가 `localStorage` 전역을 예약해 vitest jsdom 이 실제 구현을 싣지 못함 | `tests/setup.ts` 테스트 전용 Storage 셰임 |

버그 1은 네이티브 버전에도 있었으나 당시엔 dirty 의 영향이 작아 드러나지 않았다. 웹 전환으로 dirty 가 닫기 확인·이탈 경고·자동 저장을 좌우하게 되며 표면화됐다.

### 첫 CI 실행에서 드러난 문제 2건

로컬에서는 전부 통과했지만 CI 환경에서 두 잡 모두 실패했다.

| # | 증상 | 원인 | 수정 |
|---|------|------|------|
| 1 | vitest 워커가 기동조차 못 함 (`webidl.util.markAsUncloneable is not a function`) | `jsdom@30` → `undici@8` 의 engines 가 `>=22.19.0` 인데 CI 가 Node 20 을 사용 | setup-node 를 24 로, `package.json` `engines` 에 `>=22.22.2` 명시 |
| 2 | `Missing entry-point` 로 배포 실패 | `cloudflare/wrangler-action@v3` 이 번들한 wrangler 3.90 이 `wrangler.jsonc`(JSON 설정)를 읽지 못해 `env`·`assets` 를 무시 | 액션 제거, package-lock 에 고정된 wrangler 4 를 `npx` 로 직접 호출 |

함께 발견한 구조 문제: `ci.yml` 과 `deploy.yml` 이 별도 워크플로라 **병렬 실행**됐다. 테스트가 깨져도 배포가 성사될 수 있었다. `deploy.yml` 을 삭제하고 `ci.yml` 의 `deploy` 잡으로 합쳐 `needs: verify` 로 묶었다.
