## 4. marked 확장의 함정 — `start()` 에 `^` 를 쓰면 안 된다

구현 중 `가[^b] 나[^a]` 가 **`가<br>[^b] 나[^a]`** 로 렌더됐다. 인라인 코드 `` `[^1]` `` 에는 공백이 하나 생겼다.

원인은 marked 가 `start(src)` 에 **`src.slice(1)`** 을 넘긴다는 것이다(결과에 1 을 더한다). 잘려 나간 첫 글자 뒤가 문자열의 처음이 되므로 `/^\[\^/m` 이 **줄 한가운데서도 맞고**, marked 는 그 위치에서 블록을 잘라 문단을 두 동강 냈다.

확장 셋을 하나씩 켜 보는 이분 탐색으로 범인을 좁혔다. 고친 뒤에는 줄바꿈을 명시적으로 요구한다(`/\n\[\^…\]:/` + 인덱스 +1).

## 5. 검증

의도적 버그 7종을 주입해 전부 잡히는 것을 확인했다.

| 주입 | 결과 |
|------|------|
| 정의 없는 참조도 각주로 | 단위 + E2E |
| 등록부를 파싱마다 새로 만들지 않음 | 단위 6건 |
| 슬러그 정규화 제거 | 단위 (아래 참고) |
| 슬러그 충돌 회피 제거 | 단위 |
| `start()` 줄바꿈 앵커 제거 | 단위 2건 |
| 하이라이팅에서 각주를 링크보다 늦게 | 단위 2건 |
| 정의 목록 인라인 파싱 제거 | 단위 + E2E |

**슬러그 정규화는 처음에 한 번 빠져나갔다.** 이스케이프가 이미 속성을 지켜 주고 있어서 "따옴표가 새 속성을 만들지 못한다" 는 단언이 정규화 없이도 통과했기 때문이다. 정규화가 실제로 보장하는 것 — `id`/`href` 에 공백·`#` 이 들어가지 않는다 — 을 직접 단언하는 테스트를 더해서야 잡혔다. 트랩 #16 의 또 다른 사례다.

## 6. 리뷰에서 나온 결함 둘

PR 을 올린 뒤 자체 리뷰에서 두 가지가 나왔다. 둘 다 **각주가 각주를 부르는** 경우다.

| 결함 | 증상 |
|------|------|
| 목록을 `map` 으로 만듦 | `[^1]: 참고[^2]` 에서 2번 각주는 **링크만 생기고 항목이 없다.** `map` 은 시작 시점의 길이만 훑는데, 본문을 렌더하는 도중에 각주가 늘어난다 |
| 참조마다 `id` 부여 | `가[^1] 나[^1]` 처럼 흔한 문서에서 **같은 id 가 여러 개** 생긴다 |

전자는 "어디로도 가지 않는 링크를 만들지 않는다" 는 이 기능의 전제를 정면으로 깨뜨린다. 인덱스 루프로 바꾸고, id 는 처음 참조에만 붙인다. 두 결함 모두 주입해 테스트가 잡는 것을 확인했다.
