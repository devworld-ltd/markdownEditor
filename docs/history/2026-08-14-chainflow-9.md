## 3. 이번 체인의 판단들

### F-23 — 하이라이터를 직접 썼다

highlight.js·shiki 는 정확하지만 런타임 의존성이 늘고 번들이 수십~수백 KB 커진다. 대신 **지원 언어를 좁게 잡고 모르는 것은 손대지 않는** 토크나이저를 썼다. 정규식 대안(alternation) 없이 **한 번의 선형 스캔**이라 ReDoS 가 구조적으로 불가능하고, 출력은 `<span class="tok-*">` 뿐이라 기존 DOMPurify 경로(F-18)를 그대로 탄다.

어설프게 칠하는 것보다 **단색으로 두는 편이 낫다** — 틀린 색은 읽기를 방해한다.

### F-29 — "단어" 라고 쓰면 틀린 숫자가 된다

공백으로 자르면 한국어에서는 단어가 아니라 **어절**이 세어진다. 형태소 분석기는 번들을 수 MB 늘린다. 그래서 **세는 방식에 정확한 이름을 붙였다**: 한글이 섞이면 "어절", 아니면 "단어". 읽기 시간도 한글이면 글자 기준, 아니면 어절 기준이며 **10% 임계값**이 없으면 코드 주석의 한글 한 글자로 기준이 뒤집힌다.

### F-30 — 문자 수로 파이프를 맞추면 더 어긋난다

`"이름".length` 는 2 지만 표시 폭은 4칸, `"🙂".length` 는 2 지만 폭은 2칸 — **두 방향으로 다 틀린다.** `Intl.Segmenter` 로 자소를 끊고 자소마다 폭을 판정한다.

### F-54 — 회수해도 잃는 것이 없게

비우는 것은 **저장된 사본뿐**이고 편집기의 내용은 그대로다. 대상은 깨끗하고·활성이 아니고·파일 이름이 있는 탭 — 즉 **파일을 다시 열면 되찾을 수 있는 것**뿐이다. 탭 자체는 닫지 않는다.

요구사항은 "오래된" 탭이었지만 세션 스키마에 시각이 없다. 넣으려면 스키마 버전을 올려야 하고 그러면 기존 세션이 통째로 폐기된다(F-55) — **공간을 벌려다 문서를 잃는 셈**이라, 대신 큰 것부터 비워 건드리는 탭 수를 최소화했다.

## 4. 조용히 아무 일도 하지 않던 것들

이번 체인에서 **오류를 내지 않고 실패하던** 버그를 셋 찾았다. 전부 테스트가 아니라 실제 동작 확인에서 나왔다.

| 증상 | 원인 |
|------|------|
| 표 대화상자의 "정렬 맞추기" 가 아무 일도 안 함 | `showModal()` 중에는 바깥이 **inert** 라 `focus()` 가 먹지 않고, 포커스 없는 textarea 의 `execCommand` 는 조용히 무시된다. jsdom 은 inert 미구현이라 단위 테스트 16건이 전부 통과했다 |
| 열 정렬을 지정해도 프리뷰가 늘 왼쪽 정렬 | marked 는 정렬을 `align` **속성**으로 내는데, 표현 속성은 `#preview td { text-align: left }` 규칙보다 약하다. `[align]` 선택자가 없으면 **기능이 통째로 안 보인다** |
| 상태 바 추가 후 a11y E2E 8건 실패 | 랜드마크 밖 콘텐츠는 axe `region` 위반. `role="status"` 로 고치면 암묵적 `aria-live` 가 붙어 **타이핑마다 숫자를 읽는** 원래 문제가 되살아나므로 `<footer>` 로 해결 |
