### #33 — 초기화 실패 후 재시도가 막힌다

`initialized = true` 가 `try` **밖**에 있어, 초기화가 예외로 실패해도 플래그가 남았다. 이후 재시도는 "이미 초기화되어 재호출을 무시합니다" 라는 **사실과 다른 경고**와 함께 거부된다 — 한 번도 성공한 적이 없는데도.

단순히 `try` 안쪽 성공 경로로 옮기면 **새 문제가 생긴다.** 리스너 부착은 이 초기화에서 유일하게 되돌릴 수 없는 부작용이라, 한쪽 패널만 붙은 채 실패하면 재시도가 **두 번째 엔진**을 만든다. 서로 다른 상태를 가진 두 클로저가 같은 `scrollTop` 을 다투게 된다.

그래서 셋으로 나눴다.

| 상황 | 동작 |
|------|------|
| 부착 전 실패 | 잠금 없음 → 재시도 가능 |
| 부분 부착 후 실패, `removeEventListener` 있음 | 붙은 것을 떼고 잠금 해제 → 재시도 가능 |
| 부분 부착 후 실패, `removeEventListener` 없음 | **잠근 채 실패** — 엔진 중복보다 무동작이 낫다 |

`ScrollPanel` 계약에 **선택적** `removeEventListener` 를 추가했다. 실제 DOM 요소는 항상 갖고 있고, 가짜 host 는 없어도 된다.

### #34 — 렌더가 진행 중이던 동기화를 삼킨다

`reapplyAfterRender()` 는 `doSuspend()` 를 부르고, `doSuspend()` 는 대기 중인 `applyFrame` 을 취소한다. 스크롤과 타이핑을 동시에 하면 방금 만든 스크롤 한 프레임이 사라진다.

이슈에는 "다음 scroll 이벤트가 오면 복구된다" 고 적었지만 **실제로는 그보다 나쁘다.** 취소 직후 낡은 `lastRatio` 를 프리뷰에 덮어쓰므로, 사용자가 거기서 스크롤을 멈추면 **다음 상호작용까지 어긋난 채로 남는다.**

취소 **전에** 최신 비율을 확정하도록 고쳤다. 단 소스가 에디터일 때만 되살릴 수 있다 — 소스가 프리뷰였다면 그 비율의 근거인 `preview.scrollTop` 을 이미 `innerHTML` 교체가 0 으로 지운 뒤라 복원할 정보가 없다. 이 한계는 코드 주석과 아키텍처 문서에 남겼다.

## 4. 발견 사항 — `vi.spyOn` 은 이미 스파이된 메서드에 같은 mock 을 돌려준다

새 테스트가 처음에 실패했는데 **프로덕션 코드는 정상**이었다. 앞선 테스트가 `mockRestore()` 에 도달하지 못한 채 실패하면 그 spy 가 남고, 이후 `vi.spyOn(console, "warn")` 이 **같은 mock 을 반환**해 `mock.calls` 가 누적된다. `console.warn` 호출 1회를 기대한 단언이 3건을 받았다.

격리한 뒤 별도 파일에서 재현해 프로덕션 코드가 정확히 경고 1건만 내고 리스너 롤백도 되는 것을 먼저 확인했다. **테스트가 빨간불이라고 해서 프로덕션 코드가 틀린 건 아니다** — 특히 전역 객체를 스파이할 때는 오염 가능성을 먼저 배제한다.

대응: 파일 내 `vi.spyOn(console, "warn")` 3곳 모두 설치 직후 `mockClear()` 를 붙였다.
