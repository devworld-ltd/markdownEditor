# `http:` 예외를 앱 오리진이 로컬일 때로 좁힘 (#198)

> 최종 갱신: 2026-09-16 · 대상: v2.8.0

## 요청

이슈 [#198](https://github.com/devworld-ltd/markdownEditor/issues/198) — PR #196 코드 리뷰에서 나온 P2(개선 권고). "배포 환경에서도 `?url=http://localhost` 가 허용된다."

## 무엇이 문제였나

`classifyUrlParam` 은 `http:` 를 **대상 호스트가** `localhost`·`127.0.0.1`·`[::1]` 이면 통과시켰다. 이 판정에 앱 자신이 어디서 도는지가 들어가지 않아, 배포된 `https://md-editor.devworld.co.kr/?url=http://localhost:3000/...` 링크도 확인창까지 도달했다.

**보안 영향은 작다.** 사용자가 확인창에서 "열기" 를 눌러야 하고, 대상 서버가 CORS 를 열어 줘야 내용을 읽을 수 있으며, 읽은 내용은 사용자 자신의 탭에만 들어가고 밖으로 나가지 않는다. 공격자가 얻는 것이 없다.

문제는 다른 데 있다. **확인창에 뜨는 호스트가 `localhost` 라 사용자가 위화감을 느끼기 어렵다.** 그리고 배포 환경에서 이 예외가 필요한 이유가 없다 — 로컬 개발 편의를 위한 것이었다.

## 어떻게 고쳤나

`classifyUrlParam(value, appHostname)` 로 인자를 하나 늘리고, `http:` 예외를 **대상과 앱 양쪽이 모두 로컬일 때만** 열도록 했다.

```ts
if (
  parsed.protocol === "http:" &&
  isLocalHostname(parsed.hostname) &&
  isLocalHostname(appHostname)
) {
```

**앱 호스트명을 새 인자로 받지 않았다.** `readOpenIntent(href)` 의 `href` 가 이미 앱 자신의 주소이기 때문이다 — `location.href` 는 당연하고, PWA 경로도 `main.ts` 가 `new URL(href, window.location.origin).href` 로 절대화해 넘긴다. 그래서 `readOpenIntent` 안에서 `url.hostname` 을 꺼내 넘긴다.

호출부에 오리진을 구해 넘기게 했다면 **두 경로가 각자 계산**하게 되고, 그 순간 한쪽만 틀리는 길이 생긴다 — F-90/F-91 이 애초에 `readOpenIntent` 하나로 합쳐 둔 이유(M-13)와 같은 논리다. 전역도 읽지 않으므로 순수 모듈 성질은 그대로다(트랩 #15).

## 검증

단위 테스트를 8건 더했다(51 → 59).

| 덧붙인 단언 | 확인하는 것 |
|---|---|
| 앱이 배포 오리진이면 로컬 http 도 `reject(scheme)` × 3 | **이번 수정의 본체** |
| 앱 오리진이 `localhost`·`127.0.0.1`·`[::1]` 이면 예외가 열린다 × 3 | 로컬 개발이 안 깨졌다 |
| 앱이 로컬이어도 비-로컬 http 는 여전히 `reject` | 예외가 넓어지지 않았다 |
| 앱이 로컬이어도 https 는 그대로 `remote` | 예외가 https 를 가리지 않는다 |

기존 "로컬 호스트의 http 는 remote" 3건은 앱 오리진을 `https://app.test` 에서 `http://127.0.0.1:5173` 으로 바꿨다 — 배포 오리진에서 통과하던 것이 이제 통과하면 안 되므로, 이름도 "앱이 로컬일 때" 로 고쳤다.

**트랩 #16 대로 단언이 실제로 회귀를 잡는지 확인했다.** `isLocalHostname(appHostname)` 한 줄을 지워 #198 이전 동작을 주입하니 새 단언 3건이 정확히 실패했고, 되돌리니 다시 통과했다. (되돌릴 때 `git checkout` 이 아니라 사본을 썼다 — 트랩 #87.)

E2E 는 손대지 않았다. `playwright.config.ts` 의 앱 오리진이 `http://127.0.0.1:5173` 이라 `openUrl.spec.ts` 24건이 그대로 통과한다(2건은 원격 전용 skip).

**"배포 오리진에서 거절된다" 는 로컬 E2E 로 확인할 수 없다** — 앱이 로컬에서 도는 한 그 조건에 닿지 않는다. 단위 테스트가 이 경계를 지키는 유일한 수단이다.
