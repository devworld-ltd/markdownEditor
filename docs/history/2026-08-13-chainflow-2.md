## 4. F-58 — 설명이 없으면 기능 한계는 버그로 읽힌다

Safari 사용자가 `note.md` 를 저장하면 `note (1).md` 가 다운로드되고 원본은 그대로다. File System Access API 미지원이라는 브라우저 한계이지 앱 결함이 아니다.

**표시 시점을 앱 진입이 아니라 "폴백 모드에서 첫 저장을 시도하는 순간"으로 잡았다.** 아직 겪지도 않은 제약을 미리 설명하면 소음이고, 실제로 마주친 시점에 설명해야 맥락상 읽힌다. 세션당 1회로 제한했고 Chrome·Edge 에서는 표시되지 않는다(E2E 가 단언).

`showNotice()` 재사용 대신 별도 요소를 만든 이유: 저장 성공 토스트와 동시에 떠야 하는데 `notice.ts` 는 단일 슬롯이라 하나가 다른 하나를 지운다.

## 5. F-47 잔여 — 완전한 리프화가 항상 답은 아니다

`fileOps.ts` 5.19% → 89.77%. `FileOpsHost` 로 **플랫폼 API 만**(picker·Blob·anchor) 주입 경계로 뺐다.

`tabs.ts`·`notice.ts` import 는 그대로 뒀다. 이 모듈은 본질적으로 탭 상태를 바꾸는 것이 일이라 그 의존을 끊으면 호출부만 복잡해지고 이득이 없다. **검증에 필요한 것은 플랫폼 경계뿐이었다.**

이는 앞선 다섯 사례(완전 리프)와 다른 결론이며, "의존 방향을 정리하라" 가 "모든 의존을 끊으라" 는 뜻이 아님을 보여준다.
