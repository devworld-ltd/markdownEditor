## 3. F-60 이 프로젝트의 성격을 바꿨다

그전까지 이 저장소는 "서버·DB·네트워크 호출이 없는 100% 클라이언트 앱" 이었고 `wrangler.jsonc` 에 `main` 진입점조차 없었다. 이제 R2 에 문서를 저장하는 Worker 가 있다.

**공유를 쓰지 않으면 여전히 네트워크 요청이 한 건도 없다** — E2E `SH8` 이 이를 단언한다. `CLAUDE.md` 의 핵심 제약 서술을 그에 맞게 고쳤다.

## 4. 테스트가 전부 통과한 상태에서 실물 배포가 잡은 결함

이번 체인의 가장 중요한 사건이다.

**정적 자산 계층은 Worker 보다 먼저 요청을 가로챈다.** `not_found_handling: single-page-application` 이면 매칭되는 자산이 없는 GET 은 곧바로 `index.html` 로 응답되고 **Worker 코드는 실행조차 되지 않는다.**

그래서 `GET /api/share/<id>` 가 마크다운 대신 앱 HTML 을 돌려줬다. **`POST` 는 자산 계층이 다루지 않아 통과했기 때문에 절반만 동작했다** — 링크는 만들어지는데 열리지 않는 상태다.

**이때 단위 473건·E2E 253건이 전부 통과한 상태였다.** API 를 목으로 대체하면 배포 라우팅은 검증되지 않는다.

대응:
- `assets.run_worker_first: ["/api/*", "/s/*"]`
- `scripts/healthcheck.sh` 가 **실제 배포에서 공유 API 왕복**을 확인
- 그 확인은 **캐시를 우회한다** — 공유 응답은 `immutable` 이라 엣지가 대신 답하면 라우팅이 깨져도 통과한다(트랩 #19 의 공유 API 판)

## 5. Worker 가 타입 검사를 전혀 받지 않고 있었다

`worker/` 가 `tsconfig.json` 의 `include` 밖이었다. `tsconfig.worker.json` 을 만들고 `npm run typecheck` 가 둘 다 돌리게 했으며, `npm run build` 가 그것을 부르므로 CI 에서도 걸린다.

브라우저와 workerd 는 전역(`Request`·`Response`·`R2Bucket`)이 겹치면서도 달라 하나의 tsconfig 로는 다룰 수 없다.

## 7. 테스트가 가려졌던 경로 둘

- **F-34 영속화**: `page.reload()` 가 `beforeunload` 를 발화시켜 저장을 대신하고, 탭 열기의 디바운스 타이머가 재정렬 뒤에 발화해 또 한 번 가렸다. **선행 저장 완료를 기다린 뒤 언로드 없이** localStorage 를 확인해 못을 박았다.
- **F-34 `dragover`**: `preventDefault` 를 지워도 합성 `DragEvent` 로는 `drop` 이 그대로 발생한다. **취소됐는지 자체**를 단언하도록 바꿨다.
