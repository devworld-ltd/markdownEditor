## 요청

PR #196·#188 코드 리뷰에서 나온 P2(개선 권고) 잔여 3건을 처리한다.

| 이슈 | 내용 |

| [#199](https://github.com/devworld-ltd/markdownEditor/issues/199) | 확인 대화상자 재진입 시 두 번째 요청이 조용히 버려진다 |
| [#197](https://github.com/devworld-ltd/markdownEditor/issues/197) | `RemoteDocHost.notify` 가 선언만 되고 쓰이지 않는다 |

셋 다 **"오류도 없이 조용히 무동작"** 이라는 같은 실패 유형이다. 이 저장소가 반복해서 사고를 낸 유형이고(트랩 #12·#22·#75·#98), 그래서 한 PR 로 묶었다.

## #199 — 재진입

확인창이 이미 열려 있으면 `open()` 이 `return` 만 하고 끝났다. 새 요청의 `onCancel` 도 안 불려 `main.ts` 의 `cleanupAddress()` 가 돌지 않았고, 사용자 입장에서는 아무 일도 일어나지 않았다.

닿는 경로가 실제로 있다 — PWA `focus-existing`(F-89/#187)에서 확인창이 떠 있는 창에 OS 가 새 `targetURL` 을 전달할 때다.

이슈가 준 두 선택지 중 **1번(버리되 `onCancel` 은 부른다)** 을 골랐다. 근거는 코드 주석에 남겼고 요약하면:

1. **교체는 확인창을 위험하게 만든다.** 이 대화상자의 존재 이유가 "링크를 준 사람을 믿을 수 있을 때만 여세요" 인데, 사용자가 A 를 읽고 "열기" 로 손을 옮기는 사이 내용이 B 로 바뀌면 **읽지 않은 것을 확인하게 된다.**
2. **`close` 이벤트는 동기가 아니다.** `dialogEl.close()` 는 close 를 큐에 넣는다 — 교체하려면 닫기 전에 옛 핸들러를 떼야 하고, 안 그러면 뒤늦게 도착한 close 가 방금 세운 새 요청을 취소로 처리한다.

## #197 — 쓰이지 않는 주입 구멍

`RemoteDocHost.notify?` 를 지우고 `main.ts` 의 주입도 함께 제거했다. 진행 알림의 단일 통로는 `main.ts` 의 `handleIntent` 라는 것이 현재 설계이고, 이제 **타입이 그것을 강제한다** — 되살리면 `TS2353` 으로 컴파일이 막힌다.

## #189 — 중복 등록

`main.ts` 612줄의 등록이 677줄 등록에 덮여 죽어 있었다. `setTabSwitchListener` 는 슬롯이 하나다.

**동작은 바뀌지 않는다** — 덮어쓰는 쪽(677줄)이 원래 이기고 있었고, 두 등록 사이(612~677)에 탭 전환이 없으며 `initTabs()` 는 494줄로 둘 다보다 앞이다. 죽은 줄을 지우고 주석을 살아 있는 쪽으로 옮겼다.

여기에 더해 **`setTabSwitchListener` 가 기존 리스너를 교체할 때 `console.warn` 을 띄우게 했다.** 이슈가 요구한 범위를 넘는 판단이므로 근거를 적어 둔다 — 이 버그는 **아무 테스트도 실패시키지 않았고** 그럴 수도 없었다(죽은 코드라 관찰 가능한 동작 차이가 없다). 경고가 없으면 같은 실수가 다시 들어와도 같은 방식으로 조용히 지나간다. 마지막이 이긴다는 동작 자체는 그대로 뒀다 — 막으면 정당한 교체가 불가능해진다. `initOpenUrlUi` 의 이중 초기화 경고와 같은 패턴이다.

### 테스트를 쓰다 만난 것

`vi.spyOn(console, "warn")` 은 **이미 스파이된 메서드에 대해 같은 객체를 돌려줘 호출 수가 누적된다.** 앞 테스트의 경고가 남아 "첫 등록은 조용하다" 가 실패했다 — 스파이를 만든 뒤 `mockClear()` 로 초기화해야 한다. 모듈은 `loadTabs()` 의 `vi.resetModules()` 로 정상적으로 새것이었다.

### 문서 숫자를 정정했다

`feature-status.md` 의 F-90 단위 수가 `51` 로 낡아 있었는데, 직전 #198 작업에서
그것을 **재지 않고 `51 + 8 = 59` 로 이어받아** 오류를 키웠다. 실측은
`openParams` 56 · `remoteDoc` 14 · `openUrlUi` 15 = **85** 다. 이번에 실측값으로
바로잡고 내역까지 적었다 — 합계만 적혀 있으면 다음 사람도 재지 않고 더하게 된다.
#198 이력 문서와 목록의 `51 → 59` 서술도 `openParams.test.ts` 기준으로 고쳤다.
