# Finder "다음으로 열기" 등록 (이슈 #135)

## 요청

> mac finder에서 다음으로 열기 팝업 메뉴에 추가할 수 있어?

## 먼저 답한 것 — "그냥은 안 된다"

Finder 의 "다음으로 열기" 는 macOS **Launch Services** 가 채운다. `.app` 번들의
`Info.plist` 에 있는 `CFBundleDocumentTypes` 를 읽는데, **브라우저 탭에는 번들이 없다.**
v1.x 네이티브 앱 시절에는 자연히 됐지만 v2.0.0 웹 전환으로 사라진 능력이다.

그래서 "된다/안 된다" 로 답하지 않고 **되는 경로 하나와 그 제약**을 먼저 제시했다:

| 방법 | 판단 |
|------|------|
| **PWA + File Handling API** | ✅ 채택 — Chrome·Edge 로 설치하면 실제 `.app` 셸이 생기고, 매니페스트 선언이 그 번들의 문서 타입이 된다 |
| 네이티브 래퍼 `.app` | ❌ v2.0.0 방향 전환을 되돌리는 일 |

## 만든 것

| 파일 | 역할 |
|------|------|
| `public/manifest.webmanifest` | `file_handlers` 선언 |
| `src/launchFiles.ts` (신규) | `launchQueue.setConsumer()` — 주입형 리프 |

### 핸들을 그대로 넘긴다

`LaunchParams.files` 는 **`FileSystemFileHandle`** 배열이다 — 파일 선택 창으로 연
것과 같은 종류다. 그래서 `fileOps.openFileFromHandle()` 에 그대로 물렸다.

여기서 파일을 직접 읽어 탭을 만들었다면 **중복 탭 방지·최근 목록(F-36)·핸들 보관
(#125)을 다시 구현하게 되고**, 곧 두 경로가 갈라진다.

### 순서를 지켜 하나씩 연다

동시에 열면 탭 순서가 실행 인자 순서와 달라지고, 중복 탭 판정(`isSameEntry`)도
서로를 못 본 채 지나쳐 **같은 파일이 두 탭으로** 열릴 수 있다. 하나가 실패해도
나머지는 연다.

### 확장자는 두 MIME 양쪽에

`.md` 의 MIME 은 환경마다 다르고 **빈 문자열로도 온다**(트랩 #61). `text/markdown`
과 `text/plain` 양쪽에 `.md`·`.markdown` 을 걸었다.

## 검증 중 잡은 것 — `window.launchQueue` 는 대입이 안 먹는다

E2E 3건이 실패해 한동안 앱 코드에서 원인을 찾았다. 실제 원인은 테스트 쪽이었다.

`window.launchQueue` 는 **플랫폼이 제공하는 속성**이라 Chromium 이 자기 것을 되돌려
준다. 그런데 **대입 직후에는 바뀐 것처럼 보인다** — 그래서 앱이 읽을 때 원래 것이
오는 것을 알아채기 어렵다. 소비자가 영영 불리지 않으니 기능이 멀쩡한데 테스트만
실패한다.

`Object.defineProperty` 로 심어야 한다. 트랩 #81 로 남겼다 — 트랩 #60
(`DataTransferItem.prototype`)과 같은 성격이다.

## 승격 중 잡은 별건 — 릴리스 기준 태그 (#137)

직전 작업(#131)에서 만든 릴리스 흐름이 **평상시 경로를 처음 도는** 승격이었다.
그 첫 실행에서 버그가 나왔다.

```
[release] 2.1.0 → 2.2.0 (minor), 기준 태그: 없음
[release] 커밋 91건
```

`v2.1.0` 이 로컬·원격 **모두 있는데도** 못 찾았다. `git describe --tags` 는 **HEAD 의
조상**에 붙은 태그만 보는데, 이 저장소는 태그를 `main` 머지 커밋에 붙이고 릴리스
계산은 `dev` 에서 한다 — 조상 관계가 성립하지 않아 **구조적으로 영영 못 찾는다.**

그대로 진행했다면 **이미 나간 91건이 CHANGELOG 2.2.0 절에 통째로 다시 실렸다.**

`git tag --list v*` 에서 버전 순으로 직접 고르도록 고쳤다(PR #137). 정렬을 순수
함수로 분리한 이유는 사전순이면 `v2.10.0 < v2.9.0` 이 되어 **큰 갱신에서만 조용히**
틀리기 때문이다. 트랩 #83.

## 자동 테스트로 확인하지 못한 것

**"Finder 목록에 실제로 뜨는가" 는 검증하지 못했다.** Launch Services 는 OS 것이고
헤드리스 Chromium 에는 없다. 검증한 것은 **매니페스트 선언과 `launchQueue` 배선까지**다.

실기기 확인 절차:

1. Chrome/Edge 로 https://md-editor.devworld.co.kr 접속
2. 주소창 설치 아이콘 → 앱 설치
3. Finder 에서 `.md` 우클릭 → **다음으로 열기** 목록 확인
4. 골라서 열면 탭으로 뜨는지 확인

트랩 #82 로 "이 기능은 자동 테스트로 끝까지 확인할 수 없다" 를 남겼다 — 다음 사람이
E2E 를 더 짜서 해결하려 들지 않도록.
