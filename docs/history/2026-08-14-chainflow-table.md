## 3. 판단

### 파이프는 흐리게, 정렬 표식은 진하게

둘 다 문법 기호지만 성격이 다르다. 파이프는 **구조**라 눈에 띄면 글 읽기를 방해하고, 정렬 표식(`:---:`)은 **정보**다 — 편집 중에도 어느 열이 어느 쪽으로 정렬되는지 보여야 F-30 의 정렬 기능이 제 값을 한다.

### 판정을 두 벌 만들지 않는다

"구분선이 없으면 표가 아니다" 는 F-30 이 이미 내린 판정이다. `parseDelimiterRow()` 를 그대로 가져와 썼다 — 같은 질문에 두 곳이 다르게 답하면 어느 쪽이 맞는지 알 수 없게 된다.

### 계산용 함수를 렌더에 쓰지 않는다

`tableFormat.splitRow()` 는 칸을 `trim()` 한다. 파이프 정렬을 계산할 때는 그게 맞지만, **렌더에 쓰면 공백이 사라져 오버레이가 밀린다.** 이름이 맞아 보인다고 가져다 쓰면 F-23 잔여의 전제가 조용히 깨지는 자리였다.

## 4. 검증

의도적 버그 5종을 주입해 전부 잡히는 것을 확인했다.

| 주입 | 잡은 테스트 |
|------|-------------|
| 칸을 trim | 단위(글자 보존) + E2E(높이 일치) |
| 구분선 확인 없이 표로 판정 | 단위 + E2E |
| 표 상태가 끝나지 않음 | 단위 |
| 이스케이프된 파이프를 구분자로 | 단위 |
| 정렬 표식을 파이프와 같은 색으로 | 단위 + E2E |
