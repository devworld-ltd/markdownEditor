## 3. 이번 체인의 성격 — 넣었다가 지운 것이 셋

기능 6개를 더한 것보다, **검증되지 않는 코드를 남기지 않은 것**이 이번 체인의 성과다. 매 항목마다 의도적 버그를 주입해 테스트가 실제로 실패하는지 확인했고(총 32종), 그 과정에서 **아무 테스트도 실패시키지 않는 코드**가 셋 나왔다.

| 지운 코드 | 왜 |
|-----------|-----|
| F-32 의 F-25 억제 훅 | 있으나 없으나 드래그 후 두 패널의 비율 차이가 **0 으로 동일**했다. F-25 의 메아리 판별이 이미 처리한다 |
| F-39 의 `.editor-container[data-mode] #preview` 선택자 | `!important` 하나면 선택자 특이도와 무관하게 이긴다 |
| (앞 체인) F-22 의 rAF 선택 재적용 | 트랩 #2 는 탭바 클릭 경로의 이야기였다 |

반대로 **테스트로 뒷받침되지 않던 코드를 살려낸 경우**도 둘 있었다. `go()` 의 재계산과 레이아웃 병합 쓰기는 각각 다른 경로에 가려 E2E 로는 검증되지 않았고, 그 사실을 확인한 뒤 그 경로만 짚는 테스트를 새로 썼다.

## 4. 자동 점검이 잡은 것 vs 못 잡은 것 (F-59)

| 도구가 잡은 것 | 도구가 못 잡은 것 |
|----------------|-------------------|
| `#preview` 에 role 없이 `aria-label` (serious) | **탭이 `<div>` 라 키보드로 전환 불가** |
| 랜드마크 부족 | **프리뷰를 키보드로 스크롤 불가** |
| 다크에서 링크 대비 **1.37:1** | 툴바 버튼 20개에 포커스 표시 없음 |

**axe 는 통과하는데 쓸 수 없는 상태가 실재한다.** 탭이 그 예다 — 클릭 핸들러가 달린 `<div>` 는 어떤 규칙도 위반하지 않지만 키보드 사용자에게는 없는 기능이다.

링크 대비 문제는 **F-57 이 표면과 본문은 토큰화했지만 링크를 빠뜨린** 것이다. 자동 점검이 아니었으면 다크 모드 사용자만 겪고 보고되지 않았을 종류다.

## 5. 설계 판단

### 가로챌 것과 가로채지 않을 것

| 조합 | 판단 | 근거 |
|------|------|------|
| `⌘F` | **가로챈다** | 브라우저 찾기는 textarea 안을 못 본다 |
| `⌘P` | **가로채지 않는다** | 브라우저 인쇄가 곧 원하는 동작. 가로채면 대화상자 취소·미리보기만 잃는다 |
| `⌘W`·`⌘N` | 가로챌 수 **없다** | 브라우저가 선점 |

PDF 라이브러리도 넣지 않았다 — "PDF 로 저장" 은 인쇄 대화상자 안에 이미 있다.

### 정화 경로는 하나뿐 (F-38)

`htmlExport.ts` 는 마크다운을 파싱하지 않는다. 프리뷰에 이미 들어간 정화된 HTML 을 받아 감싸기만 한다. 두 번째 파싱 경로를 만들면 정화 정책이 갈라지고, 한쪽만 갱신되는 순간 F-18 이 뚫린다. **내보낸 파일은 남이 열기 때문에 앱 안보다 위험하다.**

다만 제목은 파일명에서 오므로 DOMPurify 를 거치지 않는다 → `escapeHtmlText()` 로 직접 막는다.

### 내보내기는 저장이 아니다

`exportFile()` 은 탭의 핸들·파일명·dirty 를 건드리지 않는다. 탭이 `note.html` 을 가리키게 되면 **다음 `Cmd+S` 가 마크다운 원문을 `.html` 에 덮어쓴다.**

### 실행 취소를 지키는 것이 치환의 전부 (F-22)

`execCommand("insertText")` 를 유지하고, "모두 바꾸기" 는 문서 전체를 **한 번에** 넣는다. 부분 치환을 N번 반복하면 Cmd+Z 를 N번 눌러야 하고, 치환 결과가 질의를 포함하면(`"a"` → `"aa"`) 아예 끝나지 않는다.
