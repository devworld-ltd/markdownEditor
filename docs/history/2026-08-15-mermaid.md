## 2. 먼저 물은 것 — 이 저장소의 성질이 걸렸다

이 저장소는 기능 80여 개를 더하는 동안 런타임 의존성을 `marked`·`DOMPurify` **둘로 유지**했다. mermaid 를 들이면 셋이 된다. 그래서 진행 전에 세 갈래를 물었다.

| 선택지 | 뜻 |
|--------|-----|
| 의존성 0 — 부분 자체 렌더러 | flowchart 정도만 직접 그리고 나머지는 코드블록으로 남김 |
| **mermaid 도입** ← 선택 | 문법 전체를 정확히 그림. 의존성 3개 |
| 보기 좋게만 | 그림으로 바꾸지 않음 |

사용자가 **mermaid 도입**을 택했다. 그 대가를 줄이는 것이 이번 구현의 설계 목표가 됐다.

## 3. 대가를 줄인 세 장치

| 장치 | 효과 |

## 4. 실측으로 드러난 것 둘

### `htmlLabels: false` 는 선택이 아니다

mermaid 는 기본적으로 라벨을 `<foreignObject>` 안의 HTML 로 그리는데 **DOMPurify 가 그것을 지운다.** 처음 렌더한 그림은 도형만 있고 **글자가 없었다.**

더 좁은 함정도 있었다: `flowchart.htmlLabels` 만 껐더니 **클러스터 라벨은 나오고 노드 라벨만 사라졌다.** 최상위 `htmlLabels` 까지 꺼야 한다.

정화 허용 목록에 `foreignObject` 를 여는 선택지도 있었지만, 그 태그는 임의의 HTML 을 SVG 안에 심는 통로다 — F-18 을 약하게 만드는 대신 mermaid 쪽을 `<text>` 로 그리게 했다.

### 내보낸 HTML 검사가 원문 문자열로는 안 된다

라벨이 `<tspan>` 으로 쪼개져 나가므로 `toContain("자료를 연결한다")` 가 실패한다. 내보낸 HTML 을 **실제로 파싱해** SVG 의 텍스트를 읽도록 고쳤다.

## 5. 검증 — 그리고 지운 코드

의도적 버그 7종 중 **6종이 잡혔다.** 남은 하나가 이번 작업의 수확이다.

| 주입 | 결과 |
|------|------|
| 지연 로드 가드 제거 | 단위 ✓ · **E2E 는 놓쳤다** → 아래 참고 |
| 정화 건너뛰기 | 단위 ✓ |
| `htmlLabels` 되살리기 | 단위 ✓ · E2E 3건 ✓ |
| 캐시 제거 | 단위 ✓ |
| 실패 시 코드블록 삭제 | 단위 2건 ✓ · E2E ✓ |
| 앵커 무효화 제거 | 단위 ✓ |
| **실행 토큰 제거** | **아무것도 실패하지 않았다** |

### E2E 가 지연 로드를 못 잡던 이유

네트워크 리스너를 `beforeEach` 의 `goto` **뒤에** 붙이고 있었다. 앱 기동 때 나가는 요청을 통째로 놓쳐, 지연 로드를 없애도 통과했다. 리스너를 이동 전으로 옮기고 우리 모듈(`src/mermaidView.ts`)이 아니라 **라이브러리 청크만** 세도록 고쳤다.

### 실행 토큰을 지웠다

비동기 렌더가 끝났을 때 본문이 이미 바뀌었을 수 있어 실행 토큰을 뒀는데, **어떤 테스트도 있고 없음을 구별하지 못했다.** 이유를 따져 보니 떨어져 나간 노드의 `replaceWith()` 는 원래 아무 일도 하지 않는다 — 낡은 결과가 화면에 붙는 경로가 애초에 없다.

토큰과 적용 직전 재확인을 지우고, **루프 시작의 연결 확인 하나만** 남겼다. 그것은 "낡은 문서를 그리느라 새 문서가 늦어지지 않는다" 는 관측 가능한 값이 있어서, 그 값을 재는 테스트를 새로 썼다(가드를 지우면 실패한다).
