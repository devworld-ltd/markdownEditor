# 사용자 시나리오

> 최종 갱신: 2026-08-12 · 대상: 웹 전환 (v2.0.0)

## 0. 페르소나

| 페르소나 | 설명 | 주요 니즈 |
|----------|------|-----------|
| **P1 · 개발자 도현** | README·기술 문서를 자주 쓰는 Chrome 사용자 | 코드 블록·테이블 렌더 확인, 파일 덮어쓰기 저장 |
| **P2 · 블로거 수민** | 마크다운 초안을 쓰는 비개발자 (Safari) | 설치 없이 바로 사용, 툴바로 서식 적용 |
| **P3 · 리뷰어 지훈** | 여러 문서를 오가며 확인 | 멀티 탭, 재방문 시 이어서 작업 |

**웹 전환의 핵심 변화**: 설치가 필요 없어졌고(P2 진입 장벽 제거), 대신 브라우저별로 파일 기능이 달라졌다(P1·P2 경험 분기).

## US-01 · 처음 방문해 문서를 쓰고 저장한다 (P1)

**선행 조건**: Chrome 또는 Edge, HTTPS 또는 localhost.

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | URL 접속 | 좌측 빈 textarea + 우측 빈 프리뷰, 탭 `Untitled`, 타이틀 `Markdown Editor` |
| 2 | `# 회의록` 입력 | 즉시 탭 `Untitled *`, 타이틀 `Markdown Editor *`. 150ms 뒤 프리뷰에 `<h1>`. 500ms 뒤 localStorage 자동 저장 |
| 3 | `Cmd/Ctrl+S` | 핸들이 없으므로 `showSaveFilePicker()` 로 저장 위치를 묻는다 |
| 4 | 파일명 지정 후 저장 | 디스크 기록 → 탭 `회의록.md`, `*` 제거, "회의록.md 에 저장했습니다" 알림 |
| 5 | 추가 편집 후 `Cmd/Ctrl+S` | **대화상자 없이** 같은 파일에 덮어쓰기 |

**수용 기준**: 3단계에서 취소해도 상태가 변하지 않고 알림도 뜨지 않는다.
**커버 기능**: F-01, F-08, F-09, F-14, F-19
**검증**: `fileaccess.spec.ts` — "미저장 문서 저장은 저장 위치를 물은 뒤 기록한다", "핸들이 있는 문서는 대화상자 없이 덮어쓴다"

## US-02 · Safari/Firefox 에서 사용한다 (P2)

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | URL 접속 | 동일한 편집 화면. `body[data-fs-access="false"]` |
| 2 | Open 버튼 클릭 | 숨김 `<input type="file">` 이 열려 파일을 **업로드**한다 |
| 3 | `note.md` 선택 | 새 탭 `note.md` 생성, 본문·프리뷰 표시 |
| 4 | 편집 후 `Cmd/Ctrl+S` | 덮어쓰기가 불가능해 **`note.md` 를 다운로드 폴더로 내려받는다**. "내려받았습니다" 알림 |
| 5 | 같은 파일을 다시 Open | 핸들이 없어 중복 판별 불가 → **탭이 하나 더 생긴다** |

**제약 고지**: 이 경험 차이는 브라우저 API 한계이며 우회 수단이 없다. 사용자에게 명확히 알리는 UI 는 아직 없다 ([F-58](./features/feature-status.md)).
**커버 기능**: F-07, F-08(폴백), F-11(제약)
**검증**: `fileaccess.spec.ts` — "폴백 경로" 5케이스

## US-03 · 실수로 탭/브라우저를 닫는다 (전 페르소나)

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | 저장하지 않고 편집 중 탭의 × 클릭 | `"Untitled" 의 변경 사항이 저장되지 않았습니다. 닫을까요?` 확인 |
| 2 | 취소 | 탭과 내용이 그대로 유지된다 |
| 3 | 확인 | 탭이 닫힌다 |
| 4 | 저장하지 않고 브라우저 탭/창을 닫거나 새로고침 | `beforeunload` 로 브라우저 기본 이탈 경고 표시 |
| 5 | 그래도 새로고침 | 500ms 자동 저장 덕에 **내용이 복원된다** (dirty 마커까지) |

**이전 버전과의 차이**: 네이티브 버전에는 1~5 중 어느 것도 없어 Cmd+W 한 번에 작업분이 사라졌다.
**커버 기능**: F-15, F-19, F-20
**검증**: `tabs.spec.ts` — dirty 닫기 확인/취소 2케이스, `session.spec.ts` — "새로고침 후 편집 중이던 내용이 복원된다"

## US-04 · 여러 문서를 동시에 편집한다 (P3)

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | New 버튼 또는 `Alt+N` | 빈 `Untitled` 탭 추가 및 활성화 |
| 2 | `a.md`, `b.md` 열기 | 탭 3~4개, 마지막 연 문서가 활성 |
| 3 | 탭 클릭으로 전환 | 떠나는 탭의 본문·커서·스크롤 스냅샷 → 대상 탭 복원 (**커서 위치 포함**) |
| 4 | `a.md` 를 다시 열기 (Chrome) | 중복 탭 없이 기존 탭으로 전환 |
| 5 | `Alt+W` | 현재 탭 닫기 (dirty 면 확인) |
| 6 | 마지막 탭까지 닫기 | 빈 `Untitled` 탭이 자동 생성 |
| 7 | 다음 날 다시 방문 | 마지막 세션의 탭 구성과 활성 탭이 복원된다 |

**주의**: 7단계에서 복원된 탭은 **파일 핸들이 없다.** 저장하면 위치를 다시 묻는다 (브라우저 보안 정책상 불가피).
**커버 기능**: F-05, F-06, F-11, F-12, F-20
**검증**: `tabs.spec.ts` 11케이스, `session.spec.ts` — "복원된 탭은 파일 핸들이 없어 저장 시 위치를 다시 묻는다"

## US-05 · 문법을 몰라도 툴바로 서식을 적용한다 (P2)

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | 빈 에디터에서 **Bold** | `**텍스트**` 삽입 + `텍스트` 선택 상태 |
| 2 | `안녕` 선택 후 **Italic** | `*안녕*` |
| 3 | 줄 안에서 **Heading** | 줄 맨 앞에 `## ` |
| 4 | **Link** / **Image** | `[링크 텍스트](url)` / `![이미지 설명](url)` + `url` 선택 |
| 5 | **Code Block** | 펜스 블록 + `코드` 선택 |
| 6 | 서식 버튼 클릭 직후 | `input` 재발행 → 프리뷰·dirty 갱신 |
| 7 | **New/Open/Save/Save As** 클릭 | **`input` 을 재발행하지 않는다** — 파일 액션이 문서를 dirty 로 만들면 안 되기 때문 |

**핵심 설계**: 모든 삽입에 `document.execCommand("insertText")` 를 써서 `Cmd+Z` undo 스택을 보존한다.
**7번은 웹 전환 중 발견해 고친 버그**다 ([F-50](./features/feature-status.md)).
**커버 기능**: F-04, F-16
**검증**: `toolbar.spec.ts` 16케이스

## US-06 · 신뢰할 수 없는 마크다운을 연다 (보안, 전 페르소나)

| # | 상황 | 시스템 반응 |
|---|------|-------------|
| 1 | `<script>` 가 포함된 `.md` 를 열거나 붙여넣기 | DOMPurify 가 제거 → 스크립트가 실행되지 않음 |
| 2 | `<img src=x onerror=...>` | 이벤트 핸들러 속성 제거 |
| 3 | `[클릭](javascript:...)` | `javascript:` URL 제거 |
| 4 | `<iframe>` | 제거 |
| 5 | `<em>강조</em>` 같은 안전한 인라인 HTML | 유지 |

**웹 전환에서 이 시나리오의 중요도가 크게 올랐다.** 공개 URL + localStorage 세션이 같은 오리진에 있으므로, 정화가 없으면 악성 문서가 다른 문서까지 읽을 수 있다.
**커버 기능**: F-18
**검증**: `parser.test.ts` 6케이스, `editor.spec.ts` 2케이스

## US-08 · 오프라인에서 계속 쓴다 (P1, P2)

| # | 사용자 행동 | 시스템 반응 |
|---|-------------|-------------|
| 1 | 한 번 방문해 앱을 로드 | 서비스 워커가 앱 셸(`/`, `index.html`, manifest, icon)을 캐시 |
| 2 | 네트워크가 끊긴 상태에서 재방문 | 캐시된 셸로 정상 기동. 편집·프리뷰·탭 전부 동작 |
| 3 | 오프라인에서 편집 | localStorage 자동 저장은 그대로 동작 |
| 4 | 브라우저 주소창의 설치 버튼 | 독립 창(`display: standalone`)으로 설치 |

**전제**: 서비스 워커는 **프로덕션 빌드에서만 등록**된다. 개발 서버에서는 HMR 방해를 막기 위해 등록하지 않는다.
**⚠️ 알려진 공백**: 새 버전이 배포돼도 알려주지 않고([F-69](./features/feature-status.md)), 오프라인 상태 표시도 없다(F-70). 사용자는 자신이 옛 버전을 보는지 알 수 없다.
**커버 기능**: F-61
**검증**: `hardening.spec.ts` — manifest·아이콘·sw.js 서빙, 서비스 워커 등록(배포 환경). 실제 네트워크 차단 시나리오는 수동.

## US-09 · 저장 공간이 가득 찬다 (전 페르소나)

| # | 상황 | 시스템 반응 |
|---|------|-------------|
| 1 | 큰 문서를 여러 개 열어 localStorage 5MB 한도 초과 | `saveSession()` 이 실패 |
| 2 | — | **"브라우저 저장 공간이 부족해 자동 저장이 중단됐습니다. 문서를 파일로 저장하세요."** 오류 알림 |
| 3 | 계속 편집 | 편집은 정상 동작. 자동 저장만 멈춘 상태 |
| 4 | 파일로 저장 후 탭 정리 | 저장이 다시 성공하면 알림 플래그가 해제되어 다음 실패 때 또 알린다 |

**이 시나리오가 중요한 이유**: 자동 저장이 조용히 실패하면 사용자는 보호받고 있다고 **잘못 믿게 된다.** 알림 없이는 새로고침 한 번에 작업분이 사라진다.
**커버 기능**: F-54
**검증**: `hardening.spec.ts` 2케이스, `storage.test.ts` 1케이스

## US-10 · 개발자가 배포한다 (운영)

| # | 행동 | 반응 |
|---|------|------|
| 1 | `feature/*` → `dev` PR 병합 | CI(빌드+단위+E2E) 통과 후 `markdown-editor-dev` 로 자동 배포 |
| 2 | dev 확인 후 `dev` → `main` 병합 | `markdown-editor-prod` 로 자동 배포 |
| 3 | 문제 발견 | `main` revert 후 재배포 또는 CF 대시보드에서 이전 버전 롤백 |

**전제**: `main`·`dev` 모두 브랜치 보호 규칙이 걸려 있어 직접 push 는 거부된다 ([F-66](./features/feature-status.md)). 문서 한 줄 수정도 이 경로를 거친다.
**커버 기능**: F-41, F-52, F-63, F-66
**검증**: 실제 릴리즈 2회(PR #1·#2) + dev/prod 배포 환경 E2E 각 58건
