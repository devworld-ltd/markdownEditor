# dev-e2e 힌트 — 이슈 #187 (F-88 파일 변경 감지 재읽기 · F-89 앱 중복 실행 방지)

> 생성: `aiops:dev-e2e` · Q5 보호 로직 발동 — 이 저장소는 이미 `playwright.config.ts` + `tests/e2e/` 49개 파일 · 512건 체계를 갖추고 있어 골격 생성을 **스킵**했다. 아래는 기술 스펙 "## E2E 검증 시나리오"(E1~E6)를 **이 저장소의 기존 관례**에 매핑한 구현 가이드다. 실제 `.spec.ts` 작성은 STEP 5(`dev-frontend`) 또는 후속 구현 작업에서 이 문서를 따라 진행한다.

## 1. 배치 (신규 골격 미생성 — 기존 구조에 파일만 추가)

```
tests/e2e/fileReload.spec.ts      # E1~E5
tests/e2e/launchHandler.spec.ts   # E6
```

POM/fixtures 분리 없이 이 저장소의 기존 관례를 그대로 따른다 — `tests/e2e/fixtures.ts` 하나에 모든 헬퍼가 있고 별도 POM 클래스를 쓰지 않는다(#116 도입 이전부터의 관례, 49개 기존 spec과 동일 패턴).

## 2. 기대 fixtures 패턴 (이 저장소 고유 — auth.ts/api-client.ts 아님)

이 앱은 로그인·세션이 없으므로 표준 골격의 `fixtures/auth.ts`·`api-client.ts`·`test-data.ts` 는 **해당 없음**. 대신 `tests/e2e/fixtures.ts` 의 다음 헬퍼를 그대로 재사용한다.

| 헬퍼 | 시나리오 | 이유 |
|------|---------|------|
| `installRealHandleMock(page)` | E1~E4, E6 | 핸들이 필요한 시나리오는 **반드시 이것**을 쓴다. `installFsMock()` 의 목 핸들은 `lastModified` 가 진짜가 아니어서 파일 변경 감지를 증명하지 못한다 (기술 스펙 D-8 / 트랩 #78). |
| `installFsMock(page)` | 사용 안 함(F-88 관련 시나리오 한정) | 구조화 복제가 안 되는 평범한 객체라 `lastModified` 변경을 흉내낼 수 없다. |
| `installFallbackMode(page)` | E5 | 폴백 브라우저(핸들 없음)에서 `Reload` 버튼이 `aria-disabled` 임을 확인. |

`installRealHandleMock()`(fixtures.ts:391)의 시그니처와 "다음에 열릴 파일명 변경" 헬퍼(fixtures.ts:417)를 이용해 `note.md`/`readme.md` 두 파일을 각각 시드한다.

## 3. `config.json` e2e_* 필드 해석

이 프로젝트는 `.claude/config.json` 을 쓰지 않는다 — E2E 환경 분기는 `playwright.config.ts` 자체가 담당한다(`E2E_PREVIEW` 환경변수로 로컬/원격 분기, 트랩 #9/#88). `${cf_dev_url}` 류의 변수 참조 문법은 이 저장소에 **해당 사항 없음**. dev/prod 배포 URL은 `package.json` 의 `healthcheck:dev`/`healthcheck:prod` 스크립트와 `scripts/healthcheck.sh` 인자로 하드코딩되어 있으며, E2E 자체는 로컬 dev 서버(`http://127.0.0.1:5173`)를 기본 대상으로 한다.

## 4. 마이그레이션 권고

이관은 권장하지 않는다. 이 저장소는 이미 성숙한 자체 관례(트랩 #1~#104, `docs/testing/test-plan.md`)를 갖추고 있어 표준 POM/fixtures 분리 골격으로 옮기면 기존 512건과 스타일이 갈라진다. 신규 시나리오(E1~E6)도 기존 파일 명명·헬퍼 재사용 원칙을 따르는 편이 일관성 유지에 유리하다.

## 5. package.json 배치/병합 안내

**조치 불필요.** 이 레포의 루트 `package.json` 에 이미 다음이 모두 존재한다.

- devDependencies: `@playwright/test`(^1.62.1), `typescript`(^5.9.3) — `@types/node` 는 Vite/Node 타입이 `vite`·`vitest` 의존성 체인으로 충족되어 별도 불필요.
- scripts: `test:e2e`(`playwright test`), `test:e2e:preview`(`E2E_PREVIEW=1 playwright test`), `test:e2e:report`.
- `package-lock.json` 이미 커밋되어 관리 중 — 재생성/`npm install` 불필요.

## 7. AC-20 실기기 한계 (자동 테스트 불가)

E6 은 매니페스트 선언과 `launchQueue` 배선까지만 검증한다. "Finder에서 다시 열었을 때 새 창이 안 뜨고 기존 창이 앞으로 나오는가"는 헤드리스 Chromium에 Launch Services/창 관리자가 없어 검증 불가(트랩 #82, #100과 동일 성격). 실기기 절차와 결과는 이슈 #187 댓글에 기록하는 것이 완료 조건이다.
