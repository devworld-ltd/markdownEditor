# E2E 시나리오: 링크로 로컬 파일 열기를 시작한다 (E7, AC-12)

대상 앱: {base_url}/?open=local

## 목표
"이 앱에서 로컬 파일을 열어라"는 뜻의 링크로 들어와도, 브라우저는 주소만으로 파일 선택창을 열 수 없다는 사실을 이 앱이 알고 확인창으로 안내하며, 사용자가 직접 "파일 선택"을 눌러야만 실제 파일 선택창이 뜬다.

## 사전조건
실제로 파일을 고르지는 않는다. 이 앱에는 로그인이 없다. e2e_user/e2e_pass 는 사용하지 않는다.

## 수행 단계 (순서대로, 순수 자연어)
1. 로컬 파일 열기를 뜻하는 링크로 진입한 뒤, 아무것도 누르지 않고 1초 정도 기다린다.
2. 확인 대화상자의 "파일 선택"을 누른다.

## 성공 판정 신호 (관찰 가능)
- 1단계에서: 확인 대화상자는 열려 있지만, 이 시점까지 파일 선택창이 뜬 적이 없다(0건).
- 2단계에서: "파일 선택"을 누른 뒤에야 파일 선택창이 정확히 한 번 뜬다.
- 이후 주소창의 물음표 뒤 쿼리 부분이 비어 있다.

## 부정/엣지 케이스
1단계의 "0건" 확인이 핵심 대조군이다 — 이것을 생략하면, 파라미터만으로 파일 선택창이 열려도 테스트가 통과해 버린다. 그리고 `?open=local&url=<유효 주소>`로 진입하면 로컬이 아니라 원격 문서 확인창이 떠야 한다 — `url` 파라미터가 있으면 그것이 우선이고 로컬 요청은 조용히 무시된다.

## 결과 출력 (필수 계약)
마지막 줄에 정확히 한 줄로 출력한다:
- 성공: `E2E_RESULT=PASS`
- 실패: `E2E_RESULT=FAIL: <짧은 사유>`
